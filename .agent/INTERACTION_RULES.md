# Правила взаимодействия с агентом

Этот файл необходимо полностью перечитывать перед началом работы и после каждого сжатия, восстановления или потери контекста — до выполнения следующей задачи, вместе с `.agent/PROJECT_RULES.md`.

## Инициатива и границы запроса

- Выполнять действия в рамках запроса пользователя.
- Дополнительные действия вне запроса сначала обсуждать с пользователем: что агент предлагает добавить, что это не входило в задачу и зачем это нужно.
- Дождаться согласия пользователя перед выполнением таких дополнительных действий. Не считать молчание согласием.
- Файлы в `.agent/tasks/items/` и записи в перечне предназначены для задач по коду. Настройку взаимодействия с агентом не оформлять как задачи для кода.

## Постановка и декомпозиция задач

- Пользователь задаёт основную задачу в общих чертах, после чего пользователь и агент декомпозируют её на небольшие конкретные подзадачи.
- Полный список полученных при декомпозиции подзадач записывать в файл основной задачи `.agent/tasks/items/<номер>.md` до начала их выполнения.
- Подзадачи хранить в разделе «Подзадачи» в виде Markdown-чек-листа: `- [ ]` для невыполненных и `- [x]` для выполненных.
- Формулировать каждую подзадачу так, чтобы было понятно, какой результат означает её выполнение.
- По мере выполнения сразу отмечать соответствующие подзадачи как выполненные. Частично выполненные подзадачи оставлять неотмеченными, при необходимости добавляя пояснение.
- Если при обсуждении или выполнении появляются дополнительные подзадачи вне согласованного объёма, сначала обсудить их с пользователем и после его согласия добавить в тот же список. Не удалять выполненные пункты из истории задачи.

## Статус основной задачи

- В `.agent/tasks/INDEX.md` для каждой основной задачи указывать номер, краткое описание, статус выполнения целиком и ссылку на файл задачи.
- Использовать одинаковые статусы в перечне и в файле задачи: «Не выполнена» или «Выполнена».
- Отмечать основную задачу как выполненную только после выполнения всех её подзадач и достижения ожидаемого результата.
- Пока остаётся хотя бы одна невыполненная подзадача, основная задача имеет статус «Не выполнена».
- При изменении статуса основной задачи сразу обновлять и её файл, и перечень задач. Если у выполненной задачи появляются новые обязательные подзадачи, вернуть статус «Не выполнена» в обоих файлах.
