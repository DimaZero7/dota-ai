# Правила проекта

Этот файл необходимо полностью перечитывать перед началом работы и после каждого сжатия, восстановления или потери контекста — до выполнения следующей задачи.

## Технологии и зависимости

- Язык, платформа и менеджер пакетов пока не выбраны. Не считать технологии исходного проекта требованиями этого проекта.
- Добавлять зависимости только для конкретной задачи, требующей их использования.
- Всегда указывать точные версии всех явно объявляемых зависимостей проекта. Не использовать звёздочку (`*`), диапазоны или нефиксированные версии.
- Если выбранный менеджер пакетов поддерживает lock-файл, поддерживать его согласованность с манифестом зависимостей.
- Локальные окружения, кэши, секреты и результаты сборки не добавлять в Git.
- После выбора стека документировать требования и команды настройки в `docs/ru/environment/` и `docs/en/environment/`.

## Структура и документация

- Исходный код хранить в `src/`, вспомогательные инструменты — в `tools/`.
- Общую информацию и навигацию хранить в `README.md` и `README.en.md`.
- Документацию вести в `docs/ru/` и `docs/en/`, сохраняя соответствие разделов и актуальность обеих языковых версий.
- Описывать только фактически принятые решения и доступные команды. Не представлять планы как реализованные возможности.

## Проверка изменений

- Проверять изменения способом, соответствующим задаче и выбранному стеку.
- Команды проверок и тестирования документировать в разделе `development` после их появления.
- При завершении сообщать, что проверено, и указывать ограничения проверки.

## Учёт задач

- Хранить задачи в `.agent/tasks/`.
- Перечень задач вести в `.agent/tasks/INDEX.md`: для каждой задачи указывать номер, краткое описание, статус и ссылку на файл задачи.
- Бэклог вести отдельно в `.agent/tasks/BACKLOG.md`.
- Все оформленные задачи хранить в общей папке `.agent/tasks/items/`, без отдельных папок для каждой задачи.
- Markdown-файл задачи называть её номером: `.agent/tasks/items/1.md`, `.agent/tasks/items/2.md` и далее.
- Номера назначать последовательно, начиная с 1; использованные номера не переиспользовать и существующие задачи не перенумеровывать.
- В файле задачи указывать название, описание, ожидаемый результат, полный чек-лист декомпозированных подзадач и статус выполнения целиком. Порядок декомпозиции и обновления статусов определён в [правилах взаимодействия](INTERACTION_RULES.md). При завершении записывать результат и обновлять перечень задач.
- Файлы задач не смешивать с перечнем задач и бэклогом, которые находятся в корне `.agent/tasks/`.
- При оформлении задачи из бэклога создавать номерной Markdown-файл в `items/`, добавлять запись в перечень и заменять запись бэклога ссылкой на оформленную задачу либо удалять её из бэклога.
