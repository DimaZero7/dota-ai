# 2. Получить данные для анализа

Статус: Не выполнена

## Описание

Получить максимально полные бесплатные данные о последнем завершённом матче игрока через **OpenDota и STRATZ**. Сопоставить результаты и вместе с пользователем выбрать подходящий источник или сочетание источников для дальнейшего анализа.

Профиль игрока: https://ru.dotabuff.com/players/203182675

Dota account_id: `203182675`.

Dotabuff используется как указанный пользователем профиль, а данные матча собираются через перечисленные источники. Требуемую авторизацию проходить перед использованием соответствующего сервиса. Использовать бесплатный доступ с соблюдением его лимитов.

## Ожидаемый результат

- Один зафиксированный `match_id` последнего завершённого матча игрока на момент начала сбора.
- Отдельно сохранённые исходные ответы OpenDota и STRATZ.
- Сравнение фактически полученных данных: совпадения, дополнения, расхождения и недоступные сведения.
- Согласованное с пользователем решение о подходящем варианте получения данных для проекта.

## Границы

Разрешены сбор OpenDota и STRATZ, сравнение и обсуждение итогового решения. Получение реплея, Game Coordinator и собственный парсер исключены из задачи по запросу пользователя.

Исследуется один и тот же матч на всех этапах. Если во время работы игрок завершит новую игру, выбранный матч не менять. Если матч ещё не появился у сервиса, явно зафиксировать это; другой матч для сравнения выбирать только по согласованию с пользователем.

## Подзадачи

### Конфигурация и выбор матча

- [x] Добавить URL профиля Dotabuff и `account_id` в локальный `src/config.toml`, проверить их загрузку через `src/settings.py`.
- [x] Получить доступную историю игрока и определить последний завершённый матч; записать `match_id`, время матча, время проверки и источник, по которому он выбран. Обозначить ограничения полноты истории, если они есть.
- [x] Зафиксировать контекст выбранного матча: участие игрока, герой, режим, длительность и патч; сохранять неизвестные сведения как отсутствующие, не подставляя догадки.

### OpenDota

- [x] Получить и сохранить полный доступный ответ для выбранного `match_id`, включая данные всех участников, сведения об источнике и времени получения.
- [x] Проверить наличие разобранных данных; при необходимости запросить разбор в пределах бесплатных лимитов и повторно получить результат. Зафиксировать доступность или причину отсутствия подробностей.
- [x] Составить перечень фактически полученных данных OpenDota: итоговые показатели, временные ряды, покупки, способности, варды, события, драки и другие доступные поля. Отдельно отметить отсутствующие и пустые значения.

### STRATZ

- [x] Пройти авторизацию через Steam, получить бесплатный токен и проверить его реальные лимиты. Сохранить токен в локальной конфигурации, исключённой из Git, без вывода в отчёты и логи.
- [x] Изучить доступную схему GraphQL и получить максимально полные данные того же матча, при необходимости несколькими запросами. Сохранить запросы, ответы, время получения и ошибки или частичные результаты.
- [x] Составить перечень данных STRATZ и показать, что он добавляет к OpenDota; отделить исходные показатели от вычисленных оценок сервиса.

### Сравнение и решение

- [x] Подготовить сравнение OpenDota и STRATZ для одного матча: категории и поля, детализация по времени, покрытие участников, пропуски, расхождения и уникальные сведения. Нулевое значение не считать отсутствием данных.
- [x] Сопоставить практические затраты: авторизация, бесплатные квоты, ожидание обработки, сложность поддержки и объём сохраняемых данных. Не переносить выводы по одному матчу на гарантированное покрытие всей истории.
- [ ] Представить результаты пользователю и совместно выбрать итоговый источник или сочетание источников. Записать решение и его обоснование, обновить связанную документацию RU/EN и статус задачи после достижения результата.

## Результат

Раздел «Конфигурация и выбор матча» выполнен. Профиль загружается из локального TOML. Реализовано приложение `src/apps/matches/` с клиентом OpenDota, вызываемым сервисом выбора и CLI. Повторный запуск использует сохранённый выбор без сетевых запросов и замены матча.

Зафиксирован [контекст матча](../../../data/selected_match.json):

| Поле | Значение |
| --- | --- |
| Источник истории и контекста | OpenDota |
| Проверка истории | 05.09.2026 08:47:10 UTC / 11:47:10 МСК |
| Объём истории | 20 последних доступных записей `recentMatches` |
| Матч | `8960626424` |
| Начало | 23.08.2026 07:12:39 UTC / 10:12:39 МСК |
| Игрок | `203182675`, участие подтверждено по данным матча |
| Герой | Death Prophet (`43`) |
| Режим | Ranked All Pick: `game_mode=22`, `lobby_type=7` |
| Длительность | 3122 секунды / 52:02 |
| Сторона и результат | Radiant, победа |
| Патч OpenDota | `60` → `7.41` |
| Точное буквенное обновление | Не установлено (`null`) |

При первоначальной проверке первые записи `recentMatches` и `matches?limit=20&project=patch` совпали по `match_id`. Это два метода одного источника, а не независимое подтверждение полноты истории. Выбран последний завершённый матч среди доступных OpenDota записей; наличие более новых, ещё не проиндексированных или скрытых матчей не исключено. Полная история аккаунта не выгружалась.

Раздел «OpenDota» выполнен. [Отчёт по данным](../../../data/matches/8960626424/opendota/20260905T090414.607209Z/report.ru.md) и [полный исходный ответ](../../../data/matches/8960626424/opendota/20260905T090414.607209Z/match.json) сохранены 05.09.2026 в 09:04:15 UTC. Рядом находятся английский отчёт, схема API, перечень полей всех участников и метаданные запросов с SHA-256 и заголовками оставшейся квоты. Ответ содержит 301435 байт, 43 поля верхнего уровня и всех 10 игроков.

OpenDota подтверждает `has_api=true`, `has_gcdata=true`, `has_parsed=true`, версия парсера — 22. Подробные события присутствуют, повторный запрос разбора не потребовался. Получены 31 запись objectives, 8 teamfights, 47 записей chat, 8 записей pauses и по 53 точки преимущества по золоту и опыту. Для игрока доступны 57 записей покупок, 19 улучшений способностей, 11 записей рун, по 2 записи установки observer/sentry и поминутные ряды. Пропуски, null, пустые структуры, нули и false различаются в inventory.json; необязательные поля схемы не считаются гарантированно доступными.

Реализовано приложение `src/apps/opendota/`: клиент, сервис сбора, инвентаризация и CLI. Повторный запуск создаёт отдельный снимок того же матча. Ссылка `replay_url` сохранена как часть ответа; доступность файла не проверялась.

Раздел «STRATZ» выполнен. Использована существующая авторизованная Steam-сессия профиля `203182675` и доступный бесплатный токен. Токен сохранён в исключённом из Git `src/config.toml`. Реальные заголовки API показали лимиты 8/сек, 150/мин, 1500/час и 15000/день; таблица на сайте указывает другие числа, поэтому в метаданных сохранены наблюдаемые лимиты.

[Отчёт STRATZ и сравнение с OpenDota](../../../data/matches/8960626424/stratz/20260905T091417.870926Z/report.ru.md): сохранены схема GraphQL, 13 запросов с параметрами и исходными ответами, время, HTTP-статусы, SHA-256 и квоты. Получены все 10 игроков без ошибок GraphQL. Отдельный match.json объединяет данные по playerSlot, inventory.json описывает поля и пропуски. Большие JSON локальные и игнорируются Git.

Для целевого игрока STRATZ дал 1860 обновлений позиции, 2349 здоровья, 338 применений способностей, 86 применений предметов, 882 события урона героям, 968 событий лечения и 504 добивания. Сравнённые 11 итоговых показателей игрока совпали с OpenDota. Число записей покупок (23 против 57), помощи (10 событий при итоговых 13 assists), чата и длины рядов различаются; эквивалентность событий и шкал времени не предполагается. IMP и winRates равны null. Признаки смертей, роли и результаты линий отмечены как интерпретации STRATZ, а не установленные намерения игрока. Переходы в историю аккаунтов, справочники и средние показатели других матчей исключены из запросов и перечислены в метаданных.

Реализовано приложение `src/apps/stratz/`. Проверены живые запросы, сохранность ответов, участие игроков, отсутствие токена в артефактах, построение запросов по схеме, частичные ошибки GraphQL и остановка при HTTP 429.

Подготовлено [сравнение OpenDota и STRATZ](../../../docs/ru/architecture/data-sources.md) с английской версией. Дополнительно проверены все 10 участников: 110 из 110 итоговых значений совпали. Сопоставлены детализация, пропуски, неодинаковые журналы, квоты, авторизация, сложность и размер снимков. Оба матча уже были разобраны сервисами, поэтому время ожидания очереди не установлено.

Рекомендация: STRATZ — основной источник подробных событий, OpenDota — дополнение и проверка итогов. Выбор матча через OpenDota сохраняется. Получение реплея и собственный парсер удалены из объёма задачи, а не отмечены выполненными. Окончательный выбор сочетания источников ожидает ответа пользователя; задача остаётся «Не выполнена».
