# 2. Получить данные для анализа

Статус: Не выполнена

## Описание

Получить максимально полные бесплатные данные о последнем завершённом матче игрока по цепочке **OpenDota → STRATZ → собственный парсер реплея**. Сопоставить результаты каждого этапа и вместе с пользователем выбрать подходящий источник или сочетание источников для дальнейшего анализа.

Профиль игрока: https://ru.dotabuff.com/players/203182675

Dota account_id: `203182675`.

Dotabuff используется как указанный пользователем профиль, а данные матча собираются через перечисленные источники. Требуемую авторизацию проходить перед использованием соответствующего сервиса. Использовать бесплатный доступ с соблюдением его лимитов.

## Ожидаемый результат

- Один зафиксированный `match_id` последнего завершённого матча игрока на момент начала сбора.
- Отдельно сохранённые исходные ответы OpenDota и STRATZ, доступный реплей и результат его обработки собственным парсером.
- Сравнение фактически полученных данных: совпадения, дополнения, расхождения и недоступные сведения.
- Согласованное с пользователем решение о подходящем варианте получения данных для проекта.

## Границы

Разрешено выполнение раздела «Конфигурация и выбор матча»: проверка профиля, получение доступной истории и фиксация контекста одного матча. Остальные этапы выполнять по следующим поручениям пользователя.

Исследуется один и тот же матч на всех этапах. Если во время работы игрок завершит новую игру, выбранный матч не менять. Если последний матч ещё не появился у сервиса или его реплей недоступен, явно зафиксировать это; другой матч для сравнения выбирать только по согласованию с пользователем.

Game Coordinator включён в этап получения реплея: при отсутствии рабочей ссылки у OpenDota попробовать получить параметры скачивания через авторизованное подключение Steam. Это источник сведений для скачивания, а не парсер.

## Подзадачи

### Конфигурация и выбор матча

- [x] Добавить URL профиля Dotabuff и `account_id` в локальный `src/config.toml`, проверить их загрузку через `src/settings.py`.
- [x] Получить доступную историю игрока и определить последний завершённый матч; записать `match_id`, время матча, время проверки и источник, по которому он выбран. Обозначить ограничения полноты истории, если они есть.
- [x] Зафиксировать контекст выбранного матча: участие игрока, герой, режим, длительность и патч; сохранять неизвестные сведения как отсутствующие, не подставляя догадки.

### OpenDota

- [ ] Получить и сохранить полный доступный ответ для выбранного `match_id`, включая данные всех участников, сведения об источнике и времени получения.
- [ ] Проверить наличие разобранных данных; при необходимости запросить разбор в пределах бесплатных лимитов и повторно получить результат. Зафиксировать доступность или причину отсутствия подробностей.
- [ ] Составить перечень фактически полученных данных OpenDota: итоговые показатели, временные ряды, покупки, способности, варды, события, драки и другие доступные поля. Отдельно отметить отсутствующие и пустые значения.

### STRATZ

- [ ] Пройти авторизацию через Steam, получить бесплатный токен и проверить его реальные лимиты. Сохранить токен в локальной конфигурации, исключённой из Git, без вывода в отчёты и логи.
- [ ] Изучить доступную схему GraphQL и получить максимально полные данные того же матча, при необходимости несколькими запросами. Сохранить запросы, ответы, время получения и ошибки или частичные результаты.
- [ ] Составить перечень данных STRATZ и показать, что он добавляет к OpenDota; отделить исходные показатели от вычисленных оценок сервиса.

### Реплей и собственный парсер

- [ ] При первом получении рабочей ссылки сохранить реплей выбранного матча, не откладывая скачивание до разработки парсера. Записать источник и идентификатор матча.
- [ ] Если рабочая ссылка недоступна, пройти авторизацию Steam для Game Coordinator и попробовать получить параметры скачивания реплея. Если этот путь не понадобился, отметить подзадачу как выполненную с объяснением; если реплей получить не удалось, записать причину и обсудить дальнейшие действия.
- [ ] Выбрать бесплатную библиотеку разбора и реализовать собственный обработчик реплея на её основе. Зафиксировать версии инструментов и извлекать максимально доступные полезные данные, включая события боя, состояния игровых объектов, позиции и доступные сообщения.
- [ ] Обработать сохранённый реплей и проверить соответствие выбранному матчу. Сохранить результат, перечень извлечённых данных и ограничения парсера; показать сведения, которых нет в ответах API.

### Сравнение и решение

- [ ] Подготовить сравнение OpenDota, STRATZ и собственного парсера для одного матча: категории и поля, детализация по времени, покрытие участников, пропуски, расхождения и уникальные сведения. Нулевое значение не считать отсутствием данных.
- [ ] Сопоставить практические затраты: авторизация, бесплатные квоты, ожидание обработки, сложность поддержки и объём сохраняемых данных. Не переносить выводы по одному матчу на гарантированное покрытие всей истории.
- [ ] Представить результаты пользователю и совместно выбрать итоговый источник или сочетание источников. Записать решение и его обоснование, обновить связанную документацию RU/EN и статус задачи после достижения результата.
