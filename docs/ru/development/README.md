# Разработка и проверки

[Оглавление](../README.md)

## Выбор матча

В локальном `src/config.toml` укажите профиль:

```toml
[player]
dotabuff_url = "https://ru.dotabuff.com/players/203182675"
account_id = 203182675
```

Из корня проекта запустите:

```powershell
.\.venv\Scripts\python.exe -m src.apps.matches.cli
```

При отсутствии `data/selected_match.json` команда читает последние доступные матчи OpenDota, выбирает последний завершённый по времени начала, проверяет участие игрока и сохраняет контекст. Для этого нужен интернет, ключ API не требуется. Ошибки запросов и проверки завершают команду с ненулевым кодом.

Если файл уже существует, команда выводит сохранённый выбор без сетевых запросов. Матч автоматически не заменяется; смена матча в текущем сравнении требует согласования с пользователем. При несовпадении аккаунта с сохранённой записью команда сообщает об ошибке.

Результат: [зафиксированный матч](../../../data/selected_match.json). В нём указаны источник, время проверки, герой, режим, длительность и патч. Это последний матч из доступной истории OpenDota, которая может отставать от реальной. Точное буквенное обновление патча пока не установлено.

Проверены реальный ответ OpenDota, повторный запуск без сети, выбор из несортированной истории, исключение будущих матчей и ошибки при пустой истории, несовпадении участника, противоречивом контексте и повреждённой записи.

## Подробные данные OpenDota

После фиксации матча запустите:

```powershell
.\.venv\Scripts\python.exe -m src.apps.opendota.cli
```

Команда использует account_id из настроек и существующий `data/selected_match.json`, получает полный ответ `/matches/{match_id}` и схему API. Бесплатный доступ работает без ключа. Каждый запуск делает новые запросы и сохраняет отдельный снимок; прежние снимки и выбор матча не заменяются. Заголовки оставшейся квоты записываются в метаданные; автоматических повторов при ошибках нет.

Для выбранного матча разбор уже выполнен (`has_parsed=true`, version=22), поэтому запрос повторного разбора не отправлялся. Если в будущем разбор не подтверждён, команда сохраняет ответ и отчёт со статусом `needs_parse_review` и кодом 2; автоматическая постановка в очередь разбора не реализована. Ошибки дают код 1, завершённый сбор — 0.

Результат: [отчёт OpenDota](../../../data/matches/8960626424/opendota/20260905T090414.607209Z/report.ru.md). Исходный JSON содержит всех участников; полный перечень полей и обнаруженных вложенных путей находится в inventory.json. Отчёт отличает наблюдаемые события от готовых оценок сервиса и перечисляет пропуски. Сохранённая ссылка на реплей пока не проверялась.

Проверены живой запрос, SHA-256 и размер исходных ответов, сохранение всех игроков, неизменность исходных байтов, разные состояния значений, отклонение чужого матча и противоречивого контекста, отдельные снимки при повторном запуске, явные статусы неполного и ошибочного результата. Повторно прошли проверки выбора матча. Для проверки синтаксиса без сети:

```powershell
.\.venv\Scripts\python.exe -m compileall -q src
```
