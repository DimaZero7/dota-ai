# Запуск прототипа анализа

**Текущий персональный анализ:** [профиль игрока](player-profile.md), [применение к матчу](profile-match-review.md), [авторская цепочка и команды](synthesis.md). Нижеследующие `build`/`series` и старый `import-review` относятся к первому числовому прототипу. Его отдельные ответы Codex не формировали профиль; прежний отчёт отклонён пользователем. Для передачи новых разборов наверх используется `synthesis_cli`.

[Примеры уровней 0–6](prototype-examples.md) · [Контракты](../architecture/analysis-levels.md)

Команды выполняются из корня проекта через локальное окружение Python 3.14.7. Настройки загружаются из `src/config.toml`, иначе из `src/default_config.toml`. Используются стандартная библиотека и существующий `toml==0.10.2`; отдельного API модели и дополнительных зависимостей нет.

## Данные и запуск

Первоначальная проверка прототипа выполнена на пяти матчах. Для [последующего разбора](latest-ten-analysis.md) выборка расширена до десяти последних доступных матчей игрока 203182675. Перечень, оба пика и происхождение: [prototype_matches.json](../../../data/prototype_matches.json). Всего разрешено не более десяти уникальных матчей. Исходный `data/selected_match.json` не заменяется.

```powershell
# Только при отсутствии локальных исходных ответов; обращается к бесплатным API.
.\.venv\Scripts\python.exe -m src.apps.analysis.cli sample --total 10

# Последующие команды используют локальные снимки, без сети.
.\.venv\Scripts\python.exe -m src.apps.analysis.cli build --match-id 8960626424
.\.venv\Scripts\python.exe -m src.apps.analysis.cli series
```

`sample` требует существующий токен STRATZ. Сохранённый перечень возобновляется; увеличение `--total` дополняет его следующими доступными матчами без отбора исхода/героя. Уже сохранённые полные снимки используются повторно. Лимит проверяется по объединению перечня и локальных папок матчей. Уменьшение `--total` не удаляет собранные игры. Сервис не заказывает разбор реплея, не повышает тариф и останавливается при ошибке запроса.

После клонирования больших исходных JSON нет: они исключены из Git. `sample` получает новые снимки для сохранённых ID. Точные исторические доказательства из примеров проверяются только при наличии исходных локальных снимков с соответствующим SHA-256; новый ответ API может отличаться.

## Работа с текущим Codex

CLI считает факты и формирует пакет. Текущий Codex читает пакет и возвращает структурированный разбор по `response_contract`. Ответ сохраняется отдельным JSON и проходит проверку ссылок, статуса и размера. Это обмен файлами с текущей сессией, не автоматический вызов нейросети и не имитация модельного ответа шаблоном. Реальные сохранённые примеры находятся в `data/prototype/examples/`.

```powershell
.\.venv\Scripts\python.exe -m src.apps.analysis.cli packet --match-id 8960626424
.\.venv\Scripts\python.exe -m src.apps.analysis.cli packet --series --finding cohort:7a16d9c348bbb53d
.\.venv\Scripts\python.exe -m src.apps.analysis.cli packet --series --focus-match-ids 8959040566 8958839199 --question 'Подробно оцени только упражнение для Jakiro POSITION_2; без меты.'

.\.venv\Scripts\python.exe -m src.apps.analysis.cli detail --match-id 8959040566 --start 266 --end 372 --slot 0 --kinds kill,death,buyback --fields time,target,attacker,timeDead --session jakiro-review

# Подставить фактические пути созданного пакета и ответа Codex.
.\.venv\Scripts\python.exe -m src.apps.analysis.cli import-review --packet data/analysis/ПУТЬ_К_ПАКЕТУ.json --response data/analysis/ОТВЕТ.json --session jakiro-review
```

Идентификаторы выводов доступны в `registry` результата `series`/`build`. В Python доступны `get_finding`, `list_children` и `query_events` из `src.apps.analysis.retrieval`. Последний фильтрует время, слот, типы событий и возвращаемые поля; интервал можно расширять следующим запросом. `next_offset` означает неполученные события. Параметр `--offset` продолжает страницу.

Сессия углубления сохраняется между вызовами: максимум три запроса и суммарно 8000 байт полезного ответа. Исчерпание возвращает `budget_exhausted` и непроверенные вопросы. Новое имя `--session` обозначает новый анализ; смена источников/правил требует новой сессии. Наличие JSON-pointer и корректного формата не доказывает истинность интерпретации.

## Бюджет и сохранение

По умолчанию общий бюджет 24000 байт UTF-8: 11000 на исходный пакет, 8000 на углубления, 4000 на ответ, 1000 на служебный запас. `--budget-bytes` явно меняет общий лимит. Переполнение пакета вызывает ошибку. Предпросмотры покупок и дочерних карточек содержат число пропусков. `--focus-match-ids` исключает подробные контексты других матчей с явным списком исключённых ID; без запроса их пиков делать подробные выводы о них нельзя.

Точный токенизатор, расход токенов и полный контекст текущей сессии недоступны этому Python-прототипу. `measured_model_tokens=null`; ограничение в байтах контролирует подготовленные данные, но не гарантирует размер всей переписки Codex. Эксперимент не доказывает экономию токенов или повышение точности модели.

Производные файлы находятся в игнорируемой `data/analysis/`: снимки матчей, серия, пакеты, ответы, сессии углубления и история профиля. Ключ пересчёта включает хеши источников, параметры, подписи героев и код приложения анализа. При изменении кода пересчитывается матч целиком; точечная инвалидация отдельного эпизода пока не реализована. Предыдущие версии остаются доступны, повреждение кэша вызывает ошибку. Ответы Codex не переносятся автоматически на изменившийся пакет.

`save_profile_version` сохраняет предыдущую версию, источники и изменения условий. `evaluate_followup` принимает только новые по времени, совместимые игры и не позволяет включить исходные матчи в проверку прогресса. Полученный результат можно сохранить новой версией профиля через сервис истории. Автоматического сбора будущих игр нет; сейчас тренировка имеет статус `untested`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest tools.test_analysis tools.test_analysis_series
.\.venv\Scripts\python.exe -m tools.check_analysis
.\.venv\Scripts\python.exe -m compileall -q src tools
```

13 тестов проверяют контракты, состояния полей, бюджет, зависимые окна, исключение несовместимых ролей, пропуски, историю, повреждение доказательств и ограничения проверки прогресса. Искусственные данные находятся только внутри тестов. Отдельный `check_analysis` использует текущий локальный перечень матчей, проверяет путь 0–6 и повторное использование, формирует семь пакетов и проверяет два углубления. В исходном прогоне на пяти матчах было 40 проверок; при подготовке последующего отчёта десять матчей прошли 79 проверок источников и структуры. Число проверок зависит от состава данных. Команда не генерирует новые ответы модели.

[Результат сквозного прогона](../../../data/prototype/end-to-end.json) отдельно перечисляет сценарии, проверенные только искусственно. Семантическая проверка указателей выбирает по одному событию каждого типа; это не независимая проверка истинности всех событий поставщика. Проверка текущим Codex не слепая: сессия также исследовала исходные данные.
