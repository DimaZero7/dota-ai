# Архитектура

[Оглавление](../README.md)

Приложение `src/apps/matches/` отвечает за выбор и фиксацию матча:

- `clients.py` — адаптер общего клиента OpenDota к ошибкам выбора матча.
- `services.py` — выбор завершённого матча, проверка участия игрока, получение контекста и сохранение выбора.
- `exceptions.py` — ошибки выбора матча.
- `cli.py` — загрузка настроек через `src/settings.py`, вызов сервиса и вывод результата.

Контекст хранится в `data/selected_match.json`. Повторный вызов возвращает сохранённый матч. Исходная выбранная запись истории хранится отдельно от полей контекста; в результате указаны URL источников и ограничения данных.

Приложение `src/apps/opendota/` получает подробные данные этого матча:

- `clients.py` — HTTP-клиент с тайм-аутом, фиксацией времени, SHA-256 и заголовков квоты; используется и выбором матча.
- `services.py` — проверка выбранного матча и всех участников, сохранение исходного ответа и схемы API, проверка признака разбора, создание отчётов.
- `inventory.py` — перечень полей и вложенных путей, различение отсутствующих ключей, null, пустых структур, нулей и false; отчёты RU/EN.
- `exceptions.py` и `cli.py` — ошибки интеграции и точка входа.

Каждый запуск создаёт отдельный снимок в `data/matches/<match_id>/opendota/<UTC>/`. `match.json` и `schema.json` содержат байты исходных ответов; `metadata.json` — происхождение и статус; `inventory.json` и `report.ru.md` / `report.en.md` — описание покрытия. При ошибке снимок получает статус failed, полученные ответы сохраняются. STRATZ и парсер реплея пока не реализованы.

HTTP-клиент использует стандартную библиотеку Python; дополнительных пакетов для этого этапа не требуется. [Запуск](../development/README.md).
